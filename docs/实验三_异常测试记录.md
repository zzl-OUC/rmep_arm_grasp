## 1. 测试方法

异常不能只在代码里"写了分支"就算处理了 —— 必须有**可复现的触发证据**。因此分四步：

| 步骤 | 做法 |
|---|---|
| ① 静态定位 | 通读 `classify_task_node.py` / `classify_grasp_server.py`，列出所有异常分支及其**触发条件**与**日志字段**，与文档 §三.6 列举的四类逐条对照 |
| ② 修缺陷 | 对照中发现 3 处"声称处理了但实际不成立"的缺陷（见 §6），先修再测 —— 否则测出来的"通过"是假的 |
| ③ 物理注入 | 每类异常都构造**真实物理条件**去触发（不是打桩、不是改日志、不是 mock 返回值），通过 launch 参数切换场景，**不改代码** |
| ④ 留证据 | 每场景归档 `task_log.json` + 各节点状态日志 + 识别输出；期望值先写死在脚本里，跑完逐条比对 |

一键复现（跑完自动对比四场景）：

```bash

export DISPLAY=:0 LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe
```

## 2. 异常分类与被测契约

`ClassifyGrasp.action` 的 Result 增加 **`int32 error_code`**，让四类异常在**接口层**可区分
（此前"不可达"和"抓取失败"都只记成 `failed`，任务节点 docstring 声称有 `unreachable` 但实现里没有）：

| 异常（文档 §三.6） | error_code | 触发条件 | 实现位置 | 任务日志标签 | 任务行为 |
|---|---|---|---|---|---|
| 空网格 | — | 本轮扫描窗口内该网格无任何检测 | `classify_task_node._plan` | `skipped_empty` | 跳过，不中断 |
| 未识别物体 | — | 检出框不在任何取物网格；或类别为 `unknown`／置信度 < `min_score` | `vision_classifier.process_frame` + `_plan` | `skipped_unknown` | 跳过，不中断 |
| **不可达目标** | **1** | IK 最优误差 > 2mm（目标超出可达包络） | `classify_grasp_server.ik_dz` | `unreachable` | 跳过，**不重试**（确定性失败） |
| **抓取失败** | **2** | 抬升后实体仍在台面（`z < 0.065`）= 没夹住 | `classify_grasp_server` LIFT 段 | `grasp_failed` | **重试 1 次**，再失败则跳过 |
| 运动到位失败 | 3 | 关节未收敛（`max|err| ≥ 0.06`） | `_send_arm` | `motion_failed` | 重试 1 次 |
| 非法网格/料盒 | 4 | `grid not in GRIDS` / `bin not in BINS` | `_execute` 入口 | `unknown_target` | 跳过，不重试 |
| 放置未达阈值 | 6 | 距投放点 ≥ 0.07 m | `_execute` 判定段 | `place_failed` | 重试 1 次 |

## 3. 注入方式与物理依据

四类异常都靠**真实物理条件**触发。为使注入点可计算而非试凑，先做了两项标定：

### 3.1 机械臂 IK 可达包络（`ik_dz`，容差 2 mm）

| TCP 高度 z | 可达 d 范围 |
|---|---|
| ≤ 0.03 | **完全不可达**（几何下限） |
| 0.0446（抓取高度） | 0.226 – 0.282 |
| 0.065（下降中间航点） | 0.182 – 0.326 |
| 0.14（接近/回程高度） | 0.216 – 0.358 |

→ 把 `z_grasp` 设成 **0.005**（低于几何下限）即可让 `DESCEND_GRID` 必然报 IK 不可达。

### 3.2 俯视相机视差系数：实测 **1.054**

相机把方块顶面（z≈0.05）当作 z=0 反投影，导致反投影世界坐标被径向放大。实测标定
（方块摆在格心，比对 `/grid_detections` 的 x,y 与格心真值）：

| 网格 | 真实格心半径 | 视觉反投影半径 | 系数 |
|---|---|---|---|
| cell_1 | 0.19000 | 0.20057 | 1.0556 |
| cell_3 | 0.19005 | 0.20016 | 1.0532 |
| cell_5 | 0.19000 | 0.20025 | 1.0540 |

**含义**：格心方块本身就已被"外移" 0.0103 m。若再叠加径向偏移 o，总外移 = `0.0103 + 1.054·o`，
必须 < `CELL_TOL`(0.075) 才仍判为该格 → **o < 0.0615**。

### 3.3 四类注入

| 场景 | blocks_preset | 注入的物理条件 | 依据 |
|---|---|---|---|
| S1 空网格 | `empty_grid` | 只生成 4 个方块（cell_5/cell_6 留空） | 直接构造 |
| S2 未识别物体 | `unknown_obj` | cell_4 换成**红色**方块（`block_red.urdf`）：H≈0，不在 green(35–85) / yellow(18–35) 色相带内 | 轮廓法能检出该框（面积 961 px ∈ [80,4000]），但类别投票为空 |
| S3 抓取失败 | `miss_grasp` | cell_1 方块沿径向外偏 **0.055 m**（总外移 0.0683 < 0.075，仍判 cell_1） | 该点抓取高度 d≈0.330 > IK 上界 0.282 → 可达性钳制逐级回退（k=1.0→0.0）最终落到 d=0.256 格心，夹爪对准点与方块相距 5.5 cm |
| S4 不可达目标 | `unreachable` + `z_grasp:=0.005` | 抓取高度设为低于几何可达下限 | 见 §3.1 |

> `blocks_preset` / `z_grasp` / `with_task` 三个 launch 参数为本轮新增，正常验收行为不变（默认 `normal` / `0.0446` / `true`）。

## 4. 测试结果（仿真，对照文档 §四）

`task_log.json` 末条的 `counts` 即判定依据。**四类异常全部实测通过**（文档下限是"至少 2 类"）。

### S1 空网格 —— `placed 4 / skipped_empty 2`

```
cell_5  skipped_empty  空网格
cell_6  skipped_empty  空网格
cell_1  green_block  → bin_0  placed  dist=0.020
cell_2  yellow_block → bin_1  placed  dist=0.019
cell_3  green_block  → bin_0  placed  dist=0.028
cell_4  yellow_block → bin_1  placed  dist=0.030
```

### S2 未识别物体 —— `placed 5 / skipped_unknown 1`

```
cell_4  unknown       skipped_unknown  物体颜色不属任何已知类别(未识别)
cell_1  green_block   placed  dist=0.016      cell_5  yellow_block  placed  dist=0.028
cell_2  yellow_block  placed  dist=0.023      cell_6  green_block   placed  dist=0.028
cell_3  green_block   placed  dist=0.026
```
任务计划里正好 5 格（`[('cell_1','green_block'),('cell_2','yellow_block'),
('cell_3','green_block'),('cell_5','yellow_block'),('cell_6','green_block')]`），cell_4 被排除且单独记为未识别。
**这正是文档 §四.5「6 个物体至少正确整理 5 个」的等价反面用例。**

### S3 抓取失败（任务不中断）—— `placed 1 / grasp_failed 1`

```
cell_1  green_block   retry         ec=2  夹空: 抬升后方块仍在台面
cell_1  green_block   grasp_failed  ec=2  夹空: 抬升后方块仍在台面
cell_2  yellow_block  placed        dist=0.017      ← 异常后任务继续, 未被中断
cell_3..cell_6        skipped_empty
```

> 说明：该注入点位于夹爪下降扫掠范围内，实测方块被**扫落桌外**（实体 z 发散到 -3289 / -12081），
> 而非停在原地。两者都走"抬升后 z < 0.065"这条判据 → 正确判为抓取失败、开爪中止、不污染后续格。
> 记录如实标注为"扫落型失败"，不声称是纯净夹空。

### S4 不可达目标 —— `unreachable 2`（零重试）

```
cell_1  green_block   unreachable  ec=1  IK 不可达 d=0.256 z=0.005 (最优误差 38.1mm)
cell_2  yellow_block  unreachable  ec=1  IK 不可达 d=0.256 z=0.005 (最优误差 38.1mm)
cell_3..cell_6        skipped_empty
```
单次 goal 约 20 s 即返回（HOME→APPROACH_GRID→DESCEND_MID 均可达，DESCEND_GRID 判不可达），
且**不触发重试** —— 确定性失败重试无意义，属预期行为。

### 回归验证（关键）

改动触及视觉与任务节点核心逻辑，必须证明**正常路径没被改坏**：

```
blocks_preset=normal → DONE placed=6 failed=0 skipped=0
cell_1 dist=0.034  cell_2 dist=0.018  cell_3 dist=0.026
cell_4 dist=0.027  cell_5 dist=0.020  cell_6 dist=0.018
```
✅ 仍为 **6/6**，满足文档 §四.1/§四.2（≥2 类、≥6 物体至少正确 5）。

## 6. 本轮修复的 5 处缺陷（都是"声称处理了但实际不成立"）

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | `vision_classifier` 把"框内饱和像素够多但色相不属绿/黄"的物体**静默丢弃** | 未识别物体在下游凭空消失，其网格被误判成**空网格** → 与文档把两者列为两类异常直接冲突，且"未识别"永远不可能出现在日志里 | 对 `reason=='no_class_vote'` 的框照样发 detection，`class_id='unknown'`、score 0.0（不去发 `colored_pixels<20` 的噪声框） |
| 2 | `_plan` 的 `seen` 只取**进入抓取队列**的网格 | 未识别的格子先记 `skipped_unknown`、再被当成空网格补记 `skipped_empty`，**同一格重复计数** | `seen` 改为本轮快照里**所有出现过**的网格 |
| 3 | 不可达与抓取失败都只记 `failed`；task docstring 声称会记 `unreachable`，**实现里没有** | 文档 §三.6 明确把"不可达目标"与"抓取失败"列为两类异常，日志里无法区分 | `ClassifyGrasp.action` Result 增 `int32 error_code`，仿真/真机两个 server + task 全链路打通；`NO_RETRY_CODES=(1,4)` |
| 4 | 扫描只取**最后一帧**（`self.latest` 被逐帧覆盖） | 方块落地/遮挡时漏一帧，该格**整轮**被丢（实测 S3 曾从 placed 2 掉到 1） | 改为扫描窗口内**逐格累积** `self._acc`，每格保留最新观测 |
| 5 | 扫描窗口硬编码 `scan_stable=3.0 s` | 方块第 26 s spawn，靠桌沿的方块首帧检出可晚至 spawn+8 s，3 s 窗口漏检 | 开放为参数（默认 **6.0 s**），并在注释里写明实测依据 |

## 8. 真机（RoboMaster EP）适配差异 —— 必须写进报告

实验要求文档写的是 **mechArm**，我们的实物是 **RoboMaster EP 带机械臂**。这一偏差要在报告中显式声明，
并说明我们按 RoboMaster 的等效实现方式：

| 文档/仿真的概念 | 仿真实现 | RoboMaster EP 真机实现 |
|---|---|---|
| 机械臂末端 yaw 对准网格 | `chassis_yaw_joint` 回转关节 | **臂没有 yaw** → 必须**转底盘对位**（`classify_grasp_server_real` 用驱动的 `move` 相对 theta 实现在，已实现） |
| IK 判"不可达" | `ik_dz` 最优误差 > 2 mm | **无 IK**；不可达 = 固定点位超出**工作空间闸门**。实测工作空间 x∈[0.05, 0.24]（>0.20 饱和）、z∈[0, 0.20] → 网格环半径必须 ≤ ~0.20 m |
| 抓取成功判定 | Gazebo 实体真值（方块 z 是否离台） | **无真值**：靠 `move_arm`/`gripper` 的 result 成功 + LIFT 后 `arm_position` 抬升确认（必选）+ `/grid_detections` 中目标消失（可选强确认） |
| 夹爪 | effort 接口，有开度 | **无开度反馈**，调用超时 7 s；驱动单 goal 限制、`move_arm` 硬超时 5 s、速度不可调 |
| 检测模型 | HSV 轮廓法（`use_yolo=false`） | 文档 §五.3 要求"使用前序实验训练的检测模型" —— 但**实验一的模型是 mouse/phone，实验三抓的是彩色方块**，识别必须另做（现为轮廓法，`use_yolo` 开关已留） |

**含义**：仿真侧"不可达"用 IK 触发是对的；真机侧该异常只能靠**工作空间闸门**触发，
两者语义不同，**不能把仿真结论直接搬到真机**。

## 9. 残留风险与未完成项

| 项 | 说明 |
|---|---|
| **真机异常测试未做** | 文档 §六.4 要求真机也验空网格 + 未识别；须上机。优先做这两项（不依赖 IK 标定） |
| **yaw 跑飞偶发** | 实测 S1 有一次 `cell_4` 出现 `yaw=6.744 rad`（≈386°，绕过 2π）→ `motion_failed`，重跑即 4/4。`_safe_yaw` 只护 ±π 接缝，**非本轮引入**。速度跟踪控制器在 yaw 越过 ±π 后误差符号翻转、单向持续输出。会影响"≥5/6 正确"的稳定性，建议单独立项修 |
| S3 注入型态 | 该注入点被判为"扫落型失败"而非纯净夹空；若需要纯净夹空的证据，应换一个不落在夹爪扫掠体积内的注入点 |
| 真机驱动接口 | `robomaster_ros` 的 `move_arm` 单 goal、硬超时 5 s 等约束下，多格遍历靠转底盘对位，节拍比仿真慢很多，需实测节拍 |
