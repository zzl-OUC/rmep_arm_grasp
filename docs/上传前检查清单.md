| 方案 | 做法 | 代价 |
|---|---|---|
| Git LFS（推荐） | `git lfs install && git lfs track "*.onnx"`，再从 .gitignore 删掉 `*.onnx` | 需装 lfs；免费额度 1 GB 存储 |
| GitHub Release 附件 | 仓库里放 `models/README.md` 写明下载链接 | 克隆者要手动取 |
| 直接提交 | 从 .gitignore 删 `*.onnx` | 仓库永久 +38 MB，clone 变慢 |

## 三、submodule 的坑（最容易在答辩时翻车）

`src/robomaster_ros` 是 submodule，指向上游 `jeguzzi/robomaster_ros`，本地对它有两处**未提交**修改：

- `robomaster_description/urdf/arm.urdf.xacro`（4 行）
- `robomaster_ros/robomaster_ros/client.py`（+9 行）

父仓库只记录一个 commit 指针，**这些改动不会随上传进入仓库**；而且指针指向上游，克隆者 `git submodule update --init` 拿到的是没打补丁的上游代码。另外我补的贴图符号链接也在 submodule 内，同样传不上去。

已做的缓解：补丁导出成 `patches/robomaster_ros_local_fixes.patch`，贴图修复写成 `scripts/fix_rm_mesh_texture.sh`。
**克隆后按顺序执行**（要写进 README 的快速开始）：

```bash
git submodule update --init --recursive
git -C src/robomaster_ros apply ../../patches/robomaster_ros_local_fixes.patch
bash src/arm_grasp_sim/scripts/fix_rm_mesh_texture.sh
colcon build --symlink-install && source install/setup.bash
```

更彻底的做法是把自己的 fork 设为 submodule URL（需要新建一个 fork 仓库并推送），你决定要不要做。

## 五、还需要你决定的三件事

1. **仓库可见性**：现在是 `https://github.com/zzl-OUC/rmep_arm_grasp`。课程提交通常要求 private 或指定组织仓库；公开的话真机脚本里的热点地址（`192.168.2.1`，EP 默认网关，非敏感）和 `models/` 权重都会公开。
2. **38 MB 权重怎么交付**（上面三个方案选一个）。
3. **旧视频要不要进仓库**：`videos/` 里已有 9/21 之前的两段 mp4，是旧几何录的。建议删掉换成 9/22 重录的那段，或走 Releases，别攒在 git 历史里。
