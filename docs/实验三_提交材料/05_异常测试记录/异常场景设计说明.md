## 1. 目的与验收重点

实验要求「至少正确处理空网格和未识别物体两种情况」，因此本记录以 **★空网格** 与 **★未识别物体** 为核心必测项，
要求两者都做到：
1. **识别到异常**并**按类型分别记账**（`skipped_empty` / `skipped_unknown`，不笼统记为失败）；
2. **不中断**任务，继续处理其余物体；
3. 全量写入 JSON 日志（`~/classify_logs/task_log.json`）。

附加覆盖 **抓取失败（夹空）**、**IK 不可达** 两类，验证失败分类与重试策略。

## 2. 异常注入方式与期望

异常通过 `classify_sim.launch.py` 的 `blocks_preset`（场景预设）与 `z_grasp`（抓取高度）注入，**不改动运行期代码**：

| 场景 | preset / 参数 | 注入方式 | 期望结果 |
|---|---|---|---|
| ★S1 空网格 | `empty_grid` | 只放 4 块（cell_1–4），cell_5 / cell_6 无物体 | 2 × `skipped_empty` + 4 × `placed` |
| ★S2 未识别 | `unknown_obj` | cell_4 换成**红色方块**（H≈0，不属绿 35–85 / 黄 18–35） | 1 × `skipped_unknown` + 5 × `placed` |
| S3 抓取失败 | `miss_grasp` | cell_1 方块沿径向外偏 0.055 m，超出指尖触及半径 → 必然夹空 | 1 × `grasp_failed` + 1 × `placed`（任务不中断） |
| S4 IK 不可达 | `unreachable z_grasp:=0.005` | 抓取高度 0.005 m 低于机械臂几何可达下限（z≈0.03） | 2 × `unreachable`（不重试） |

## 3. ★核心必测项实测结果（各连续两次，结果一致）

### ★S1 空网格（`empty_grid`）

| 轮次 | placed | skipped_empty | skipped_unknown | failed | 用时 |
|---|---|---|---|---|---|
| 第 1 次 | 4 | **2** | 0 | 0 | 230 s |
| 第 2 次 | 4 | **2** | 0 | 0 | 236 s |

```
placed=4  cell_1(dist 0.015) cell_2(0.018) cell_3(0.027) cell_4(0.030)
skipped_empty=2  cell_5 / cell_6（本轮快照从未出现 → 判为空网格）
failed=0
```

判定依据在 `classify_task_node._plan`：`seen` 取本轮**所有出现过的网格**，`ALL_GRIDS - seen` 记 `skipped_empty`。
（注：`seen` 必须包含「出现了但因未识别而进不了队列」的网格，否则同一格会被重复计一条 `skipped_unknown` + 一条 `skipped_empty`——2026-09-14 已修。）

### ★S2 未识别物体（`unknown_obj`）

| 轮次 | placed | skipped_unknown | skipped_empty | failed | 用时 |
|---|---|---|---|---|---|
| 第 1 次 | 5 | **1** | 0 | 0 | 332 s |
| 第 2 次 | 5 | **1** | 0 | 0 | 306 s |

```
cell_4  cls=unknown  score=0.0  → skipped_unknown
        reason=物体颜色不属任何已知类别(未识别)
其余 5 格正常 placed（cell_1/2/3/5/6）
```

红色方块 H≈0 落在绿/黄区间之外 → `vision_classifier` 上报 `unknown` → 任务跳过该格**且不中断**，其余 5 块照常分类放置。

## 4. 附加异常验证

### S3 抓取失败（`miss_grasp`）

```
cell_1  green_block  retry        error_code=2  夹空: 抬升后方块 z 仍在台面
cell_1  green_block  grasp_failed error_code=2  夹空（重试 1 次后仍失败）
cell_2  yellow_block placed       dist=0.017   ← 失败后任务继续，未中断
cell_3/4/5/6 skipped_empty；1 条 skipped_unknown（偏移后落在网格外的检测）
```

抓取失败（error_code=2）属**非确定性**失败 → 重试 1 次；仍失败则记 `grasp_failed` 并**继续下一格**。

### S4 IK 不可达（`unreachable`, `z_grasp:=0.005`）

```
cell_1  unreachable  error_code=1  IK 不可达 d=0.256 z=0.005 (最优误差 38.1mm)
cell_2  unreachable  error_code=1  同上
```

IK 不可达（error_code=1）属**确定性**失败 → **不重试**（见 `NO_RETRY_CODES=(1,4)`），直接记账继续。

### 正常路径回归

```
DONE placed=6 failed=0 skipped=0     # 异常处理改动未破坏正常验收路径
```

## 5. 异常分类与重试策略（实现对照）

| error_code | 记账标签 | 是否重试 | 触发场景 |
|---|---|---|---|
| —— | `skipped_empty` | —— | 本轮快照未出现的网格 |
| —— | `skipped_unknown` | —— | 检测框不在任何网格 / 类别非绿黄 / 置信度 < 0.5 |
| 1 | `unreachable` | **不重试** | IK 不可达（确定性） |
| 2 | `grasp_failed` | 重试 1 次 | 夹空 |
| 3 | `motion_failed` | 重试 1 次 | 关节未收敛 |
| 6 | `place_failed` | 重试 1 次 | 放置未达判定阈值 |

## 6. 已知问题与诚实记录

1. **S1 首轮未出 summary（环境问题，非代码缺陷）**：批次首轮 S1 的 `classify_grasp_server` 在控制器就绪后 **2013 s** 才输出「就绪」，状态机一行未打印，最终超时。判定为**上一轮残留 `gzserver` 抢占 CPU**（脚本 `cleanup()` 只 sleep 3–5 s，清理不彻底）。清残留后复跑即正常（两次 236 s / 230 s 均出 summary）。
   → 加固：重跑前显式确认无残留 `gzserver`。
2. **cell_4 偶发 `motion_failed`**：某次复跑 S1 出现 1 条 `motion_failed`（error_code=3，`yaw=6.744 q1=0.888 q2=0.103`），重试后仍失败；随后两次复跑 cell_4 均正常 `placed(0.030 / 0.027)`。
   判定为**偶发**：cell_4 位于可达包络边缘，下降段关节收敛裕度小（cell_4 在代码注释中本就有「下降失败」前科）。**非系统性缺陷**。
   后续可做：为 cell_4 下降段增加中间航点裕度，或单独放宽其收敛判据。
3. `motion_failed` / `place_failed` 两类**未单独注入验证**（与 S3 同源路径），不在本轮范围。
